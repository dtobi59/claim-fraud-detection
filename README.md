# Warranty Claim Fraud Detector

An AI-powered pipeline that reviews vehicle warranty claims against a policy document, scores them for potential fraud, collects supporting evidence, and renders a final decision (**Approve**, **Reject**, or **Escalate to HITL**). The pipeline is exposed through an interactive **Streamlit** web app where users can upload a CSV of claims, run the multi-agent analysis, review results, and export the output.

## Overview

The core of this project is a chain of four LLM-driven "agents" (implemented with [LangChain](https://www.langchain.com/) + [LangGraph](https://www.langchain.com/langgraph) state types and an Azure OpenAI chat model) that process each warranty claim row-by-row:

1. **Policy Check Agent** – Reads the warranty policy manual (parsed from a PDF) and determines whether the claim is `Covered by policy` or `Not covered by policy` based on vehicle type, mileage, days since purchase, and the part being claimed.
2. **Fraud Scoring Agent** – Analyzes the claim and the policy check result to produce a fraud-likelihood score between `0` and `1`.
3. **Evidence Collector Agent** – Compares the claim against the policy and fraud indicators to list any red flags or policy violations (or `No issues` if none are found).
4. **Action Agent** – Synthesizes the outputs of the previous three agents into a final decision: `Approve claim`, `Reject claim`, or `Escalate to HITL` (human-in-the-loop). If the LLM response can't be parsed into one of these decisions, a conservative rule-based fallback is used instead.

Every prompt/response pair generated by each agent is recorded into a per-claim `agent_trace`, which can be inspected later in the Streamlit UI to understand exactly how a decision was reached.

## Features

- 📄 **CSV upload** of warranty claims (one claim per row).
- 🤖 **Multi-agent LLM pipeline** (policy check → fraud scoring → evidence collection → final decision) powered by Azure OpenAI via LangChain.
- 📑 **Policy-aware reasoning** — the agents read an actual warranty policy PDF (`data/AutoDrive_Warranty_Policy_2025.pdf`) and reason against it.
- 📊 **Results dashboard** with KPI cards (Total / Approved / Rejected / Escalated) and a color-coded, styled results table.
- 🔍 **Agent conversation trace viewer** — inspect the exact prompt and response for each agent, per claim.
- ⬇️ **CSV export** of the fully processed results (original columns + `policy_check`, `fraud_score`, `evidence`, `decision`, `agent_trace`).
- 🐳 **Dockerized** for easy deployment.

- Python 3.11+

## Installation

1. **Clone the repository / navigate to the project folder**

   ```bash
   cd Claim-fraud-detector
   ```

2. **Create and activate a virtual environment**

   ```bash
   python -m venv .venv
   .venv\Scripts\activate      # Windows
   # source .venv/bin/activate # macOS/Linux
   ```

3. **Install dependencies**

   ```bash
   pip install -r requirements.txt
   ```

## Configuration

The app loads credentials from a `.env` file at the project root via `python-dotenv`. Create (or update) `.env` with your own Azure OpenAI credentials:

```env
AZURE_OPENAI_API_KEY="<your-azure-openai-api-key>"
AZURE_OPENAI_ENDPOINT="https://<your-resource-name>.openai.azure.com/"
```

Optional:

- `POLICY_TEXT` — override/supply policy text directly as an environment variable. If not set, the app automatically loads and parses `data/AutoDrive_Warranty_Policy_2025.pdf`. If neither is available, a placeholder string is used.

> ⚠️ **Security note:** `.env` contains sensitive credentials and should never be committed to version control. Add it to `.gitignore` and rotate any keys that may have been exposed previously. The `deployment_name` (`gpt-5-mini`) and `api_version` (`2024-02-01`) are hard-coded in `main.py` — update them in `AzureChatOpenAI(...)` if your Azure deployment uses a different name or API version.

## Usage

### Run the Streamlit app

```bash
streamlit run app.py
```

Then open the URL shown in the terminal (typically `http://localhost:8501`).

**Workflow in the UI:**

1. Upload a CSV file of warranty claims (see expected format below).
2. Click **Generate Results** to run the claim through the four-agent pipeline. A progress bar shows per-row progress.
3. Review the **Results summary** KPI cards (Total / Approved / Rejected / Escalated).
4. Inspect the **Detailed Results** table, color-coded by decision.
5. Select any row under **Agent conversation trace** to expand and read the exact prompt/response of each agent for that claim.
6. Click **Download Results as CSV** to export the processed claims.

### Expected CSV input format

Based on the sample dataset (`data/warranty_claims.csv`), each row represents one claim with columns such as:

| Column               | Description                                   |
|----------------------|------------------------------------------------|
| `claim_id`           | Unique claim identifier                        |
| `model`              | Vehicle model (must indicate "Four-Wheeler" or "Two-Wheeler") |
| `purchase_date`      | Date the vehicle was purchased                 |
| `claim_date`         | Date the claim was filed                       |
| `days_since_purchase`| Days elapsed since purchase                    |
| `mileage`            | Vehicle mileage at time of claim               |
| `part_replaced`      | Part being claimed                             |
| `part_cost`          | Cost of the replacement part                   |
| `labor_cost`         | Labor cost                                     |
| `total_cost`         | Total claim cost                               |
| `invoice_present`    | `1`/`0` flag indicating an invoice was submitted|
| `image_present`      | `1`/`0` flag indicating supporting images exist |
| `previous_claims`    | Number of previous claims filed                |

The pipeline adds `policy_check`, `fraud_score`, `evidence`, `decision`, and `agent_trace` columns to the output.

### Use the pipeline programmatically

```python
import pandas as pd
from main import process_claims

claims_df = pd.read_csv("data/warranty_claims.csv")

def on_progress(current, total):
    print(f"Processed {current}/{total}")

results_df = process_claims(claims_df, progress_callback=on_progress)
results_df.to_csv("processed_claims.csv", index=False)
```

## Development Notes

- `agent.ipynb` contains the original Jupyter notebook used to prototype the agent pipeline found in `main.py` — useful as a reference or for interactive experimentation.
- `pytorch_file.py` is a standalone educational script that implements token embeddings and scaled dot-product attention from scratch using PyTorch. It is **not** part of the claim-processing pipeline and has no dependency on the rest of the app.

## Decision Logic Summary

| Condition                                                                 | Decision            |
|----------------------------------------------------------------------------|----------------------|
| Policy check = "Not covered by policy" and no strong justification to approve | Reject claim        |
| Evidence ambiguous and fraud score > 0.5                                   | Escalate to HITL     |
| Claim is covered, evidence clean, fraud score low                         | Approve claim        |
| LLM response unparseable (fallback, rule-based)                           | Based on `policy_check` ("Not covered" → Reject) and `fraud_score` (> 0.5 → Escalate, else Approve) |
